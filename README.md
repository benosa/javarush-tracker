## Сборка и тесты

Нужны JDK 17 и Maven 3.9.x:

```sh
mvn clean verify
```

PostgreSQL, SMTP и настоящие OAuth-ключи для тестов не нужны. Профиль `test`
поднимает H2 в памяти. Его ключ JWT — отдельная тестовая фикстура.
Тесты сбрасывают только тестовую схему перед сценариями.
H2 не заменяет проверку настоящих PostgreSQL-миграций: для него выделен упрощённый
SQL-скрипт, а частичный индекс активных назначений заменён вычисляемым столбцом.
Перенос вложенных задач между спринтами реализован на JPQL, без рекурсивного native SQL.

## Запуск контейнеров

```sh
cp .env.example .env
# Заполнить DB_PASSWORD и JWT_SECRET в .env.
# Для JWT_SECRET сгенерировать значение: openssl rand -base64 32

docker compose up --build -d --wait
docker compose ps
```

Открыть [приложение](http://localhost:8081) или [Swagger](http://localhost:8081/doc).
Compose читает `.env`; Spring получает значения из окружения контейнера.
База и сервер не публикуют порты на хост, nginx слушает `127.0.0.1:8081`.
Порт можно изменить через `HTTP_PORT`, одновременно изменив `APP_URL`.
`docker compose down` сохраняет данные. Подробнее: [контейнеры](doc/containers.md).

Для локального запуска без Docker нужно создать PostgreSQL-базу `jira` и передать
параметры окружения в IDEA либо терминале:

```sh
export DB_URL=jdbc:postgresql://localhost:5432/jira
export DB_USER=jira
# DB_PASSWORD и JWT_SECRET — свои значения из .env или менеджера секретов.
export APP_URL=http://localhost:8080
mvn spring-boot:run
```

Java сама не загружает `.env`. Для экспорта файла с корректным shell-синтаксисом:
`set -a; . ./.env; set +a`, после чего переопределить `APP_URL` для локального порта.
`!test` выбирает PostgreSQL, включая профили `default` и `prod`.
Для производственного профиля: `--spring.profiles.active=prod` при запуске JAR.

## Конфигурация

`src/main/resources/application-secrets.properties` содержит ссылки на окружение,
а не реальные пароли или ключи. `.env` исключён из Git и Docker build context.

- `DB_URL`, `DB_USER`, `DB_PASSWORD` — подключение к PostgreSQL.
- `JWT_SECRET` — минимум 32 случайных байта в Base64; обязателен вне тестов.
- `JWT_TTL` — срок JWT, по умолчанию `PT30M`, допустимо от минуты до суток.
- `COOKIE_SECURE=true` — для HTTPS; локальный HTTP использует `false`.
- `APP_URL` — внешний адрес, в том числе для ссылок в письмах и Swagger.
- `GITHUB_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET`, `GITLAB_CLIENT_ID/SECRET` —
  подключаются отдельно; полные имена переменных указаны в `.env.example`.
- `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_AUTH`, `MAIL_STARTTLS` — SMTP.
- `TEST_MAIL` — получатель писем в непроизводственном профиле.

Без OAuth-ключей работает вход по паролю. Для OAuth нужно зарегистрировать callback
`{APP_URL}/login/oauth2/code/{provider}` у соответствующего провайдера.
По умолчанию SMTP смотрит на `localhost:1025`; настоящий почтовый сервер нужно настроить отдельно.
Тестовый профиль не отправляет письма.

Исходные коммиты upstream содержали чувствительные настройки. Удаление их из текущих
файлов не удаляет старую историю; при использовании настоящих учётных данных их следует заменить.

## Демонстрационные данные

Новая база получает схему и справочники. Для просмотра доски на **пустой локальной базе**
можно выполнить `src/main/resources/data4dev/data.sql`:

```sh
docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
  < src/main/resources/data4dev/data.sql
```

Скрипт очищает существующие демонстрационные записи; не применять к рабочим данным.
Примеры входа: `user@gmail.com / password` (DEV), `manager@gmail.com / manager`
(MANAGER), `admin@gmail.com / admin` (ADMIN), `guest@gmail.com / guest` (без роли).
Изображения вложений из исходных демонстрационных записей в репозиторий не входят.

## API тегов и время задачи

После входа `POST /api/auth/login` с JSON
`{"username":"user@gmail.com","password":"password"}` ответ содержит `accessToken`.
В Swagger вставить его в **Authorize**; в запросах использовать `Authorization: Bearer <token>`.

- `GET /api/tasks/{id}/tags` — теги задачи.
- `POST /api/tasks/{id}/tags` с `{"tag":"backend"}` — добавить тег.
- `DELETE /api/tasks/{id}/tags/{tag}` — удалить тег.

Тег содержит 2–32 символа без HTML, крайние пробелы удаляются. Регистр сохраняется.
Добавление и удаление повторно безопасны; изменения блокируют строку задачи в транзакции.

`TaskTimingService.timeInDevelopment(Task)` возвращает `Duration` от `in_progress`
до `ready_for_review`; `timeInTesting(Task)` — от `ready_for_review` до `done`.
Суммируются завершённые циклы; дубли начала не сбрасывают время. Открытые, отменённые
и прерванные возвратом в разработку интервалы не учитываются.
Промежуточные `review`, `ready_for_test`, `test` входят во второй интервал согласно заданию.

Три записи ACTIVITY для примера добавлены в PostgreSQL changelog вместе с зависимыми
демонстрационными сущностями под контекстом `timing-demo` (отрицательные ID).
Чтобы применить их на отдельной демонстрационной базе, установить
`LIQUIBASE_CONTEXTS=schema,timing-demo`. Получится 4 часа 30 минут разработки и
1 час 30 минут тестирования. По умолчанию этот пример не заполняет рабочую базу.

## JWT и интерфейс

JWT подписывается HS256; проверяются подпись, issuer, audience, срок действия,
актуальный пользователь и версия его токенов. Роли берутся из БД на каждом запросе.
`POST /api/auth/logout` отзывает все выданные токены пользователя и очищает cookie.
Смена пароля, отключение или удаление пользователя делают старые токены непригодными.
HTTP Basic и авторизация через `JSESSIONID` больше не используются.

Для переходов между серверными страницами JWT хранится в HttpOnly/SameSite=Lax cookie.
Страница передаёт его в память скрипта; jQuery и отправка форм добавляют Bearer-заголовок.
В localStorage и URL access token не записывается. Изменяющие запросы не принимают
одну лишь cookie; также проверяется Origin. Приложение не включает межсайтовый CORS.
В nginx передаются внешний Host и протокол; backend доступен только внутри сети Compose.

OAuth state привязан к браузеру и одноразовый. Регистрация и сброс пароля используют
одноразовые ссылки на 15 минут, работающие без исходной сессии браузера.
Эти временные записи находятся в памяти одного экземпляра: перезапуск требует новой ссылки;
для нескольких реплик понадобилось бы общее хранилище. В пароле ожидающей регистрации
сохраняется хэш, а не открытое значение.

На главной странице переключатель Русский / English сохраняет выбор в cookie `language`.
Язык письма берётся из запроса регистрации или восстановления, включая передачу в почтовый сервис.
