# JiraRush: карта проекта

JiraRush — доска задач: проект → спринты/беклог → задачи и эпики.
Java 17, Maven, Spring Boot 3.0.2. Зависимости и их версии задаёт `pom.xml`.

## Модули

- `login`: пользователи, роли ADMIN/MANAGER/DEV, вход, OAuth и подтверждение почты.
- `profile`: настройки уведомлений и контакты пользователя.
- `bugtracking/project`, `sprint`, `task`: проекты, спринты, задачи и история изменений.
- `bugtracking/attachment`: метаданные вложений в БД, содержимое в `attachments/`.
- `bugtracking/tree`, `dashboard`, `report`: дерево, доска и отчёты.
- `ref`: справочники; ReferenceService держит справочные значения в памяти.
- `mail`: шаблоны, отправка писем и запись неудач в mail_case.
- `common`: конфигурация, общие репозитории, обработка ошибок и валидация.

Пакеты `internal` обозначают границу модуля по соглашению; компилятор её не контролирует.
В исходной версии есть обращения между такими пакетами.

## Данные и обработка запросов

Схема и справочники находятся в `src/main/resources/db/changelog.sql`.
`users` связан с `user_role`, `profile` и `contact`; `project` с `sprint` и `task`.
`activity` хранит историю задачи, `task_tag` — набор тегов.
`user_belong` связывает пользователя с объектом по типу и идентификатору.
Для этой полиморфной связи нет внешнего ключа к каждому типу объекта.

REST-контроллеры принимают DTO, вызывают сервисы или общие Handlers.
MapStruct преобразует DTO и Entity. Репозитории Spring Data обращаются к БД.
TaskService управляет статусом, спринтом и назначениями; ActivityService — историей.
UserHandler нормализует пользователя и кодирует пароль; MailService формирует письма.
UI-контроллеры возвращают Thymeleaf-шаблоны из `resources/view`.
jQuery отправляет запросы из `resources/static/js`; nginx раздаёт статику в контейнерах.

## Отправные точки проверки

- `/doc`: Swagger; `/view/tree`: дерево; `/ui/dashboard`: доска; `/ui/reports`: отчёт.
- ADMIN управляет пользователями и справочниками; ADMIN/MANAGER — проектами и спринтами.
- API остальных объектов требует аутентификацию; проверка роли не заменяет проверку владельца.
- Тестовый набор исходной версии: 142 теста, PostgreSQL на порту 5433.
- Пустая рабочая БД получает схему и справочники. Демонстрационные записи лежат отдельно
  в `src/main/resources/data4dev/data.sql`; это не миграция рабочих данных.

При дальнейших изменениях добавляем новые changeset, а не удаляем историю Liquibase
из существующей базы. Исторические SQL-запросы проверяем отдельно при переходе на H2.
